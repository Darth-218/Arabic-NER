# AraBERT — Error Analysis (issue 5.4)

**Owner:** Member 3 (Omar Hesham) · **Status:** filled from the full test run
(test F1 **0.9142**, validation F1 0.9202 used for model selection).

## How to reproduce

```bash
# 1. Tuned model (config = lr 5e-5, 4 epochs, max_len 128)
python src/approach_3_arabert/train.py --config configs/arabert.yaml

# 2. Canonical predictions for the held-out test split
python src/approach_3_arabert/predict.py --model_dir results/models/arabert \
  --split test --out results/predictions/arabert_test.jsonl

# 3. Canonical metrics + diagnostics
python src/evaluate.py --model arabert --split test --config configs/arabert.yaml
```

Outputs: `results/predictions/arabert_test.jsonl`, `results/metrics/arabert.json`,
`results/plots/arabert_confusion.json`, `results/plots/arabert_classification_report.txt`.
The headline metrics below are generated by `evaluate.py`, not hand-edited.

## Error taxonomy (span level, test split)

Matching is one-to-one by overlap: a gold span is `correct` only if the predicted
span has the same start, end **and** type; otherwise it is classed by what
differs. Predicted spans left unmatched count as `spurious`. The taxonomy
reproduces the official score exactly (TP 10,349 → P 0.9093 / R 0.9192).

| Category | Spans | % of gold spans (11,259) |
| :--- | ---: | ---: |
| Correct (span + type) | 10,349 | 91.92% |
| Right boundary, wrong type | 399 | 3.54% |
| Wrong boundary (same type) | 273 | 2.42% |
| Wrong boundary and type | 88 | 0.78% |
| Missed entirely | 150 | 1.33% |
| Spurious predicted spans (of 11,381 predicted) | 272 | 2.39% of predictions |

Wrong labels dominate: 487 of the 910 missed gold spans (53.5%) have a detected
span with the wrong type. For 399 of those the boundary is exactly right; the
other 88 also differ in boundary. Boundary tuning alone therefore cannot
recover most of the gap — type disambiguation is the main lever.

## Type confusions (count, matched overlaps)

| Gold → predicted | Count |
| :--- | ---: |
| LOC → ORG | 152 |
| ORG → LOC | 98 |
| ORG → PER | 79 |
| PER → ORG | 88 |
| LOC → PER | 42 |
| PER → LOC | 28 |

LOC↔ORG is the single largest confusion pair (250 spans), which fits WikiANN:
institution-like place names and place-like organization names share vocabulary,
and both frequently appear as multi-word annexations.

## Representative examples

Token-level tags; the erroneous part is the bracketed span.

**Wrong type, boundary intact** (place name tagged as organization):

```
وأحمر اللون معروف بإسم أناغالس حقلي .
gold: O O O O B-LOC I-LOC O
pred: O O O O B-ORG I-ORG O
```

**Wrong type plus missed head word** (organization tagged as place, first word dropped):

```
منع تفكك الاتحاد السوفيتي هذه الأهداف من أن تتحقق .
gold: O B-ORG I-ORG I-ORG O O O O O O
pred: O O I-LOC I-LOC O O O O O O
```

**Boundary over-extension** (person span absorbs the following common noun):

```
وهو الأبن غير الشرعي ألكسندر دوما الأب .
gold: O O O O B-PER I-PER O O
pred: O O O O B-PER I-PER I-PER O
```

**Boundary split** (one location split into two):

```
** عمان ( مدينة ) ( سفارة )
gold: O B-LOC I-LOC I-LOC I-LOC O O O O
pred: O B-LOC O I-LOC I-LOC O O O O
```

**Missed entity + spurious span from a foreign name**:

```
Kang So-ra on Twitter ( Korean )
gold: O O O B-ORG O O O
pred: B-PER I-PER O O O O O
```

The last case is a label-noise-flavoured error: the dataset marks "Twitter" as
ORG but not "Kang So-ra", while the model detects the person and drops the
organization. Errors of this shape are a reminder that WikiANN annotations for
transliterated names are inconsistent, so not every error is a model defect.

## Takeaways

- ORG is the weak class (0.8843): long, transliterated and place-like names.
- Most remaining errors are type errors on correctly located spans (53.5%),
  so a type-aware second pass or CRF-style label transitions would help more
  than more boundary data.
- No truncation effects at `max_len` 128; the score is not an artefact of
  truncation.
- Arabic-specific normalization is already applied at inference via the model's
  `resolved_config.json`, so the prediction file echoes original surface forms
  while the model reads normalized text.
